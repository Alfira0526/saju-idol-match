# 수익화(광고) 검토 — 5인 페르소나 토의 (2026-07-27)

> 안건: **서버 유지비 상쇄를 위한 광고 삽입** 검토. 팀장 소집, 5인 페르소나 토의 후
> 적용 방안·결정 필요 사항 정리. 조직: [`../team-personas.md`](../team-personas.md).

## 팀장 — 안건 프레이밍
- **현재 실비용은 사실상 0.** 정적 앱=GitHub Pages(무료), 유일한 서버=Cloudflare Worker인데
  최근 KV 큐+10분 Cron 배치로 최적화해 **무료 티어(10만 req/day) 내**에 안착. 즉 "지금 당장
  비용을 메워야 하는 상황"은 아니다.
- 그러므로 광고는 **"비용 상쇄"보다 "성장 대비 수익화 준비"** 관점으로 본다. 바이럴로 트래픽이
  튀면 Worker 유료 전환($5/mo)·대역폭 이슈가 생길 수 있고, 그때 수익원이 있으면 완충이 된다.
- **판단 기준: 최초 기획의도(오로지 사주로 오락적 최애 추천)와 방금 개선한 첫 진입 UX를
  광고가 훼손하면 안 된다.** 각 전문가에게 렌즈별 검토를 지시한다.

## 개발자 — 기술·리스크
- **호스팅 약관.** GitHub Pages는 "상거래가 주목적인 사이트"를 제한한다. 소규모 광고/제휴로
  운영비를 메우는 수준은 통상 용인되나, 광고가 사이트의 주목적처럼 커지면 **Cloudflare
  Pages/Netlify로 이전 검토** 필요(무료·정적 그대로 이전 가능). → 확인 필요 항목.
- **광고는 서버비를 직접 줄이지 않는다.** 유일 비용인 Worker는 광고와 무관. 광고는 별도 수익.
- **성능/개인정보.** 디스플레이 광고 스크립트는 모바일 로딩·CLS(레이아웃 이동) 부담 + 3rd-party
  쿠키 → **쿠키 동의 배너 + 개인정보처리방침** 필요(개인정보보호법). 현재 앱은 localStorage만
  쓰고 워커엔 PII 미전송(IP 해시)인데, 광고망을 붙이면 추적이 새로 생긴다.
- **난이도 순.** 제휴 링크(쿠팡 파트너스)=스크립트/동의 불필요, 링크만 → 최소. 카카오
  애드핏/애드센스=스크립트+동의+심사 → 중. → **제휴 우선이 기술적으로 가장 안전.**

## 기획자 — 기획의도·재미
- 일반 배너 광고는 "오로지 사주로 최애 추천"의 **몰입·순수성**을 깨고 싸구려 인상을 준다. 결과
  플로우 상단·중간 배너는 반대.
- 반대로 **결과와 맥락이 맞는 제휴는 경험의 '확장'**이 된다: 매칭된 최애의 **앨범·포토카드·굿즈
  보러가기**(쿠팡 파트너스)는 덕질 동선의 자연스러운 다음 스텝 → 온테마·가치 부가. 이건 광고가
  아니라 **기능**처럼 붙일 수 있다.
- 결론: 무맥락 디스플레이 광고는 결과 플로우에서 배제, **맥락 제휴 카드는 채택** 권장.

## 디자이너 — UX/사용자 친화성
- 방금 첫 진입 마찰(팝업→토스트)·필터를 정리했다. **상단/전면 배너·인터스티셜·자동 팝업은
  그 개선을 되돌린다 → 금지.**
- 배치 원칙: **가치 전달 후(결과 순위 아래)** 단 1개 유닛, 네이티브 스타일(카드), 접힘 가능.
  계산 버튼·폴드 위 노출 금지. 모바일 하단 sticky 광고=안티패턴 → 금지.
- 제휴 카드는 앱 톤(Y2K/핫핑크)에 맞춰 네이티브로 디자인, iframe 광고보다 우선.

## QA — 품질·리스크·측정
- 광고는 실패 모드를 늘린다: CLS로 순위 카드 밀림, 광고 차단기에서 레이아웃 깨짐, 느린 광고
  스크립트가 렌더 블로킹. → **광고 실패/차단 시에도 코어 계산·필터·공유가 정상**이어야 함
  (graceful degrade). qa-checklist에 항목 추가.
- **측정 없으면 판단 불가.** 수익 vs 이탈률(바운스)·계산 완료율을 비교할 수단 필요(정적 앱이라
  분석 없음 → 최소 GA4나 제휴 대시보드로 클릭·전환만이라도).
- 컴플라이언스: 쿠키 동의·개인정보처리방침·**제휴 표기("쿠팡 파트너스 활동으로 수수료 제공받음")
  필수**. 미표기 시 법적 리스크.

## 팀장 최종 판정 — 단계적 적용 방안
현재 비용이 0에 가까우므로 **UX를 해치며 서두르지 않는다.** 저마찰·온테마부터, 필요 시 확장.

### Phase 0 — 지금 (결정)
- 침습적 디스플레이 광고는 **보류.** 현 무료 티어로 충분.

### Phase 1 — 저마찰·온테마 수익화 (권장 시작점)
- **쿠팡 파트너스 제휴**: 결과 순위 **아래**에 "최애 <이름> 덕질 아이템 보러가기" **네이티브
  카드 1개**(앨범·포토카드 검색 링크). 광고 스크립트·쿠키 동의 불필요, 온테마, UX 리스크 최소.
- **후원 링크**(선택): 푸터에 Buy Me a Coffee/토스 아이디 1줄.
- **필수**: 제휴 표기 문구, 링크 rel="sponsored". 클릭 수 측정(제휴 대시보드).

### Phase 2 — 트래픽 성장 시 디스플레이 광고 (전제조건 충족 후)
- **카카오 애드핏**(국내 모바일 최적) 네이티브 유닛 1개, 결과 아래. (대안: 애드센스 — 심사·
  '운세' 콘텐츠 정책 확인 필요)
- **전제조건(선행 필수)**: ① 쿠키 동의 배너 ② 개인정보처리방침 페이지 ③ GitHub Pages 상업이용
  약관 확인(필요 시 Cloudflare Pages 이전) ④ CLS/성능 예산 검증.

### 가드레일 (모든 단계 공통)
폴드 위·계산 차단·인터스티셜·자동 팝업·하단 sticky **금지**. 결과 아래 1유닛·네이티브·
graceful degrade. 제휴/광고 표기·개인정보 고지 필수. 수익 vs 이탈률 측정.

## 결정 필요 (사용자)
1. **시작 범위**: Phase 1(제휴만) / Phase 1+2 준비 병행 / 지금은 보류.
2. **제휴 채택 여부**: 쿠팡 파트너스 맥락 카드(결과 아래)를 기능으로 넣을지.
3. **후원 링크** 노출 여부(푸터).
