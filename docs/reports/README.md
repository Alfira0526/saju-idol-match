# 주간 운영 리뷰 리포트

매주 주간 운영 리뷰 루틴이 `docs/reports/<YYYY-MM-DD>-review.md` 로 리포트를 남긴다.
프로세스 정의는 [`../OPS_ROUTINES.md`](../OPS_ROUTINES.md), 조직은
[`../team-personas.md`](../team-personas.md).

## 파일명
`YYYY-MM-DD-review.md` — 리뷰 실행일(UTC 기준, 세션에서 확인한 실제 날짜).

## 권장 양식
```markdown
# 주간 운영 리뷰 — YYYY-MM-DD

## 1. 지표 요약
- 총원 / 그룹 / 정합성(stats==idols, 중복)
- 카테고리 커버리지(노출·문턱 미달), 소속사 분포
- 제보 백로그: 추가 대기 / 오류 대기 / 처리 완료 (전주 대비 증감)
- i18n 진척(%)

## 2. 오류 처리 내역
- 확증·수정한 데이터 오류(대상, 근거 출처), inbox-done 반영 건수
- 오신고로 정리한 건

## 3. 페르소나 리뷰
- QA / 개발자 / 기획자 / 디자이너 관찰 → 팀장 종합·판정

## 4. 개선 제안 (승인 대기)
- 재미 / UX / 기술 — 각 항목에 근거와 예상 효과. **큰 변경은 여기 '제안'으로만.**

## 5. 신규 데이터·기능 아이디어

## 6. 다음 주 액션
```

## 원칙
- 확증된 데이터 오류만 자동 수정. 큰 변경은 **제안**으로만 남기고 승인 대기.
- 작업 브랜치에만 push. PR 생성·다른 브랜치 push 금지.
